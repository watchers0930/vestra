### F01. [심각도 HIGH] components/rights/RightsScoreCard.tsx:31 — 미입력 보증금을 시장 전세가율로 대체 표시

- **문제:** `claimRatios.jeonseRatio`가 null이면 `riskAnalysis.jeonseRatio`로 폴백한 뒤 `전세가율 (D/V)`로 표시한다. 실제 서버의 `analyze-service.ts:211`은 후자를 시장 전세가율 또는 시장 평균 보증금/시세로 계산한다. 실제 계약 보증금을 입력하지 않아도 개인 계약의 비율이 확인된 것처럼 보이며, 시장 데이터도 없으면 0%가 표시될 수 있다. 새 점수 카드에서 발생하는 의미 변경이다.
- **발생 조건:** D 미입력, `claimRatios.userDeposit=null`, `claimRatios.jeonseRatio=null`, `riskAnalysis.jeonseRatio=78` → 화면은 `전세가율 (D/V) 78.0%`.
- **수정 제안:** D/V는 `claimRatios.jeonseRatio`만 표시하고 null은 `미입력/미확인`으로 유지한다. 시장 참고치는 `claimRatios.marketJeonseRatio`를 별도 라벨로 표시한다. 레거시에도 D의 출처가 확인되지 않으면 실제 계약 비율로 추정하지 않는다.
- **계약/완료 기준:** §2.3, §3.4, §4.1. D 미입력·0·양수와 시장 데이터 유무 조합에서 시장 참고치가 실제 계약 비율로 표시되지 않아야 한다.

### F02. [심각도 HIGH] app/(app)/rights/hooks/useRightsAnalysis.ts:32 — 공용 훅의 보증금 입력이 리뉴얼 화면에는 연결되지 않음

- **계약/완료 기준:** §0.2, §3.4, §6 단계 1. 두 권리분석 화면에서 D 입력/삭제 후 실제 POST body의 값/필드 생략과 응답 `claimRatios`를 확인한다.

### F03. [심각도 HIGH] app/(personal-home)/renewal/jeonse/hooks/useJeonseChecklist.ts:37 — 계정·물건 구분 없이 레거시 체크 상태 자동 복원

- **문제:** 분리된 훅이 기존 단일 키 `vestra_jeonse_checklist_v1`을 무조건 복원하고 같은 키에 계속 영속 저장한다. 회원/주소 입력이나 세션 변경 초기화가 없다. A 계정·A 물건에서 완료한 확인 항목이 B 계정·B 물건에서도 완료로 표시될 수 있다. 기존 코드의 문제를 새 설계에서도 유지한 상태다. `lib/store.ts:196`의 계정 격리용 `clearAll()`도 이 키를 지우지 않는다.
- **수정 제안:** DB 미적용 동안 서버 저장 비활성은 유지하되, 임시 체크는 세션·선택 주소 범위로 제한하고 전환 시 초기화한다. 레거시 값은 자동 적용하지 말고 대상 주소를 확인하는 명시적 가져오기로 분리한다. 향후 서버 저장 활성화 시 GET/PUT, revision/409, 직렬화, 서버 저장 성공 시각을 구현한다.
- **계약/완료 기준:** §2.1, §4.5. DB 비활성 자체는 결함으로 세지 않는다. 다만 로그인/로그아웃/계정·주소 전환 시 이전 완료 항목이 승계되지 않아야 한다. 실제 교차기기 저장은 현재 미구현이다.

### F04. [심각도 HIGH] app/(personal-home)/profile/components/ProfileDashboardPanel.tsx:164 — 계정 전환 후 이전 계정의 모달 메타데이터 잔류

- **문제:** `useAnalysisDetail.ts:114`는 계정 변경 시 상세·openId를 초기화하지만, 모달 표시 조건인 부모의 `selected`는 초기화하지 않는다. 모달의 주소·종류·날짜는 계속 이전 `selected`에서 전달된다. 열린 모달 상태에서 세션이 바뀌면 상세 본문만 없어지고 이전 계정의 주소와 날짜, 삭제 버튼은 남는다. 상세 응답 무효화만으로는 설계의 개인 데이터 초기화가 완료되지 않는다.
- **수정 제안:** 모달 선택 상태도 사용자 ID에 귀속시키고 세션 변경 시 함께 닫는다. 렌더 단계에서도 선택 당시 사용자와 현재 사용자가 다르면 이전 record를 표시하지 않도록 한다. 상세 훅과 부모의 선택 상태를 함께 초기화하는 구조로 정리한다.
- **계약/완료 기준:** §4.3, §5.2. A 상세 열린 상태 및 A 요청 대기 상태 각각에서 B/로그아웃으로 전환해 A의 주소·날짜·본문이 남지 않는지 확인한다. 서버의 본인 소유 조회 조건은 구현돼 있으며, 이 지적은 클라이언트 잔류 표시 문제다.

### F05. [심각도 MED] components/rights/graph/graph-types.ts:109 — 부기등기를 별도 채권 노드와 위험 경로로 중복 집계

- **문제:** 빌더가 `isSupplementary`, `order`, `subOrder`를 무시하고 을구의 모든 행을 독립 노드로 만든다. 같은 근저당의 변경 부기도 유효 권리 수와 고위험 노드 수에 추가되며, 서로 연결된 별개 채권인 것처럼 `critical` 경로를 만든다. 기존 빌더를 새 파일로 옮겼으나 §4.8 보정은 빠졌다.
- **검증:** 실제 `buildGraph`를 메모리에서 실행했다. 근저당 주등기 1건(1억원) + 같은 순위 부기 1건(`isSupplementary=true`, 1억원) 입력에서 1억원 노드 2개와 `property → eulgu_0 → eulgu_1`, `level=critical`을 반환했다. 합성 fixture 검증이며 실등기 검증은 아니다.
- **수정 제안:** 주등기·부기 관계를 유지하고 변경/이전/말소를 원권리에 연결한다. 독립 채권 수·금액·참고 지수에는 같은 권리를 중복 반영하지 않는다. 전파 경로는 엔진이 확인한 관계를 사용한다.
- **계약/완료 기준:** §4.8. 주등기+변경/이전/말소 부기 fixture에서 독립 채권이 늘어나지 않아야 한다.

### F06. [심각도 MED] components/rights/graph/RightsGraphNode.tsx:65 — 포커스만 가능한 노드이며 근거 열람·말소 토글이 없음

- **문제:** 노드는 `tabIndex=0`인 `listitem`이지만 클릭·Enter/Space 처리나 펼침 내용이 없다. 표시 DTO도 접수일·순위·원문 detail을 버려 원문 근거를 열 수 없다. 말소 권리까지 기본 목록에 모두 들어가며 말소 보기 토글도 없다. 일반적인 영향 설명을 읽는 것만 가능해 설계의 탐색 기능이 완료되지 않았다.
- **수정 제안:** 서버/파서의 접수일·확인 가능한 순위·원문 근거를 표시 DTO에 보존하고, 버튼/펼침 패널로 클릭과 키보드 열람을 제공한다. 현행 권리를 기본으로 두고 말소 보기 토글과 순위·배당을 확정할 수 없는 조건을 명시한다. 같은 내용을 텍스트 목록에서도 제공한다.
- **계약/완료 기준:** §4.8. 키보드만으로 각 노드의 실제 근거를 열고 닫을 수 있어야 하며, 말소만 있는 경우도 오류가 아닌 빈 상태로 안내해야 한다.

### F07. [심각도 MED] app/(personal-home)/profile/components/AnalysisCompareReport.tsx:62 — 640px 고정 리포트가 모달보다 넓고 PDF 캡처도 클리핑 위험

- **문제:** 리포트 폭은 640px 고정인데 모달은 `max-w-lg`(512px)이고 본문 좌우 padding이 48px이다. 데스크톱에서도 본문보다 넓고 360px 화면에서는 가용 폭이 약 280px로 줄어 현재/직전 표의 오른쪽 열을 한 화면에서 읽을 수 없다. 모달 본문은 `overflow-y-auto`이며 전용 리포트가 그 내부에 그대로 있어, 화면 너비를 위한 고정값이 PDF까지 조상 overflow 클리핑에 노출시킨다. PDF 실제 잘림 여부는 브라우저 확인이 필요하다.
- **수정 제안:** 화면 리포트는 가용 폭에 맞추고 모바일 표의 열 배치/가로 스크롤을 명시적으로 설계한다. PDF는 동일 내용을 overflow 제한 없는 별도 캡처 컨테이너 또는 클론에서 640px로 렌더링하고, 캡처 전에 조상 스크롤 제한을 해제한다.
- **계약/완료 기준:** §4.3. 360px·데스크톱에서 현재/직전 값과 긴 주소를 확인하고, 아래로 스크롤한 상태·긴 다중 페이지 PDF에서도 전체 폭/높이가 보존되는지 검증한다.

### F08. [심각도 MED] components/rights/RightsScoreCard.tsx:47 — 등급 문구만 공용 정책이고 게이지 색상은 기존 기준 유지

### F09. [심각도 MED] app/(personal-home)/profile/components/AnalysisDetailModal.tsx:127 — 공통 이력 모달 교체로 계약·예측 등 기존 상세 요약이 사라짐

- **문제:** 부모는 종류와 관계없이 모든 이력을 새 모달로 열지만, 본문은 권리/전세 지표만 가진 비교 리포트를 표시한다. 기존 모달의 `extractKeyMetrics(selected.type, selected.data)`와 `selected.summary` 표시는 제거됐고, `record.summary`는 전달만 하고 사용하지 않는다. 계약/예측/사업성 이력을 열면 기존의 종류별 주요 수치와 요약 대신 권리 안전점수·전세가율의 `비교 불가` 목록을 보게 된다. 권리/전세 레거시 원문이 없을 때도 보존된 요약을 볼 수 없다.
- **수정 제안:** 권리·전세 비교와 다른 분석 종류의 상세 표시를 분기하고, 저장된 요약을 일반 텍스트로 복원한다. 경량 목록으로 종류별 수치를 얻을 수 없다면 필요한 상세 DTO를 명시적으로 확장하되 요약에서 숫자를 추정하지 않는다. 원문 부재 상태도 구별한다.
- **계약/완료 기준:** §4.3 및 플랫폼 연관 기능 회귀 규칙. 계약/예측/사업성 각각 기존 이력과 원문 없는 레거시를 열어 유효한 종류별 정보 또는 명확한 미지원 안내가 표시돼야 한다.

### F10. [심각도 MED] app/(personal-home)/profile/components/AnalysisCompareReport.tsx:98 — 위험요인 비교가 건수만 표시하고 항목 내용을 누락

- **문제:** API는 추가/해소 위험요인의 ID 배열과 현재/직전의 `metrics.riskFactors` 설명을 제공한다. 리포트는 배열 길이만 출력하고 요인 내용은 어디에도 표시하지 않는다. 서로 다른 위험요인이 같은 개수로 바뀐 경우 어떤 위험이 생기거나 해소됐는지 상세 화면과 PDF 양쪽에서 알 수 없다. 비교값이 null인 경우도 설명 없이 변화 항목 자체가 사라진다.
- **수정 제안:** 추가 ID는 현재 위험요인, 해소 ID는 직전 위험요인에서 설명·심각도를 찾아 표시한다. 설명이 없으면 식별 가능한 ID/정보 없음 안내를 제공하고 null은 비교 불가로 명시한다. 같은 DOM을 PDF에도 사용한다.
- **계약/완료 기준:** §4.3. 추가/해소 각각 1건, 변화 없음, 레거시 null에서 항목과 상태를 구분해 읽을 수 있어야 한다.

| 체크리스트 API | 프론트 GET/PUT 호출 자체가 없다. DB 미적용 계약 때문에 서버 저장 비활성 안내는 적절하다. 서버 코드 산출과 프론트 저장/충돌/재조회 구현 완료를 구분해야 한다. |
| 중복 fetch | 신규 상세 조회는 행 선택 시에만 발생하며 렌더 자체에서 fetch하지 않는다. 재열람마다 다시 조회하는 동작만으로 중복 요청 결함으로 판단하지 않았다. 실제 네트워크/성능 프로파일링은 미실시했다. |
| 리렌더 | 그래프 빌드는 `useMemo([parsed])`, PDF 라이브러리는 클릭 시 동적 로드한다. 체크리스트의 15항목 그룹 재구성 등을 근거 없이 성능 결함으로 세지 않았다. |
| 접근성 | 모달 role/제목 연결/초기 포커스/Tab 순환/Escape/복귀 로직은 있다. 그래프 상호작용 누락은 F06. 보조공학 및 실제 브라우저 포커스 검증은 미실시했다. |
| 구조 | 변경 페이지 `rights/page.tsx` 313줄, `JeonseRenewalContent.tsx` 398줄, `RightsResult.tsx` 404줄, `RightsInputCard.tsx` 424줄. 기존 대형 그래프·전세 콘텐츠 분리는 확인했다. |

## 검증 결과와 누락

- **통과:** 변경 프론트 파일 및 신규 `graph/` 대상 ESLint, `npx tsc --noEmit --incremental false`.
- **통과:** `npx vitest run --config lib/ux-tests/vitest.config.ts` — 3파일 57테스트. 정책·정규화·서버 API/서비스 중심이며 인증/Prisma 등 mock을 포함한다. 프론트 DOM·실제 DB·실제 저장 동작 통과를 뜻하지 않는다.
- **재현:** F05의 부기등기 중복을 실제 빌더 함수의 합성 입력 실행으로 확인했다. 저장소에 테스트/코드 파일을 추가하지 않았다.
- **누락:** 실제 로그인 계정 전환, 360px 화면, 키보드/스크린리더, PDF 파일 생성·다중 페이지, 저장/삭제 실패 후 복구, 실제 등기/주소 데이터 검증은 실행하지 않았다. F07의 PDF 클리핑은 구현상 위험으로 분리했다.
- **누락:** 전체 `npm run build` 및 기존 전체 테스트는 미실행이다. 정적 검사와 57개 계약 테스트만으로 배포 준비 완료라고 판정하지 않는다.
- **DB 조건:** DB 적용 명령을 실행하지 않았다. 체크리스트 서버 저장·교차기기 E2E는 DB 미적용 및 프론트 미연결 상태로 미검증이다.
- **우선순위:** F01~F04를 먼저 해결한 뒤 F05~F10을 처리한다. 수정 후 실제 사용자/물건 전환, 두 분석 화면의 요청 body, 모바일 비교/PDF, 부기등기·종류별 이력 회귀를 확인해야 한다.
