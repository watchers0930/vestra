## 1. 기능 개요

전세 위험도 수치와 경고가 서로 다른 결론을 주는 문제를 먼저 해결하고, 판단 근거 설명·이전 분석 비교·계약 준비 상태의 연속성을 보강한다. 위험을 낮게 보이도록 화면만 조정하지 않고 파싱 → 평가 → 응답 → 화면 → 저장 이력/PDF까지 같은 정의를 사용한다.

| 번호 | 기능 | 임차인이 얻는 결과 | 우선순위 |
| --- | --- | --- | --- |
| ① | 선순위채권·보증금 비율에 따른 위험도 보정 | 부담 비율이 커질수록 위험이 낮아지는 모순 제거, 85% 고위험 보장 | P0, 최우선 |
| ② | V-Score 축별 의미·산정 근거 설명 | 무엇을 확인했고 무엇을 아직 모르는지 이해 | P1 |
| ③ | 마이페이지 이전 결과 비교·PDF | 동일 물건의 과거 대비 변화 확인과 결과 보관 | P1 |
| ④ | 회원·주소별 계약 체크리스트 서버 저장 | 다른 기기에서도 계약 준비 상태 유지 | P1, 보안 필수 |
| ⑤ | 안전점수와 고위험 경고 영역 분리 | 숫자의 의미와 즉시 확인할 위험을 함께 파악 | P0, ①과 함께 |
| ⑥ | 전용면적 파싱 보강 | 해당 호수의 전용면적을 정확히 확인 | P1 |
| ⑦ | 도로명·지번 주소 완전표시 | 분석 대상 물건과 동·호수 식별 | P1 |
| ⑧ | 권리관계 그래프·종합위험도 시각화 보강 | 보증금보다 앞선 권리와 위험 근거를 이해 | P1 |

P0는 점수의 신뢰성에 직접 영향을 주는 출시 차단 결함이다. P1 역시 이번 8건의 필수 범위이며, 선택 기능을 뜻하지 않는다.

### 1.1 범위와 제약

- 이번 작업은 기획 문서 작성만 수행한다. 아래 파일명·모델·API·점수표는 후속 구현을 위한 제안이다.
- 후속 구현의 DB 구조 산출물은 `prisma/schema.prisma` 수정과 `scripts/sql/` 마이그레이션 SQL 파일 생성까지만 허용한다. `db push`, `migrate dev/deploy/reset`, `db execute` 또는 SQL 클라이언트·직접 연결을 통한 실제 DB 적용은 실행하지 않는다.
- 서버 인증·입력 검증·본인 소유 조건은 필수다. 프론트에서 버튼을 숨기는 방식으로 권한 검사를 대신하지 않는다.
- 신규·수정 파일은 500줄 이내로 유지한다. 현재 500줄 초과 대상은 분리 후 수정한다. 전역 대규모 리팩터링은 범위에 넣지 않는다.
- 기존 Next.js App Router, TypeScript, Prisma/PostgreSQL, NextAuth, CSS Module/Tailwind, 공용 UI·PDF 유틸을 따른다. 신규 UI·차트·검증 라이브러리 도입을 전제로 하지 않는다.
- 새로운 외부 데이터 계약·OCR 서비스 도입·과거 결과 일괄 재산정·실제 DB 적용·배포는 이번 기획의 실행 범위 밖이다.

## 4. 기술 요구사항

### 4.1 ① 위험도 산정과 등급의 근본 보정 — P0

#### 지표·데이터 계약

기존 `totalClaimsAmount`는 모든 법적 선순위를 확정한 값이 아니다. 신규 임차인 관점에서 확인 가능한 현행 권리의 채권 금액을 합산하되, 순위·금액이 미확인인 권리는 별도로 알린다. 새 임차인의 보증금을 기존 등기 전세권 금액으로 대체하지 않는다.

| 기호/지표 | 정의 | 화면 설명 |
| --- | --- | --- |
| C | 확인 가능한 선행 근저당·저당 및 선순위 금액 권리 합계 | 실제 대출잔액을 모르면 등기상 채권최고액 기준임을 표시 |
| V | 사용자가 입력한 유효 시세 또는 근거가 있는 추정 시세 | 입력/추정 여부와 기준시점 표시 |
| D | 현재 검토 중인 계약의 실제 전세보증금 | 시장 평균과 별도 필드. 미입력 시 계산 불가 |
| 선순위/시세 비율 | C ÷ V × 100 | 기존 `evaluateTotalClaims`와 이어지는 기본 지표 |
| 선순위/보증금 비율 | C ÷ D × 100 | 내 보증금 규모와 선행 채권을 비교하는 보조 지표 |
| 전세가율 | D ÷ V × 100 | 실제 계약값 기반. 시장 평균 기반 값은 ‘지역/시장 참고 전세가율’로 구분 |
| 합산 부담률 | (C + D) ÷ V × 100 | 내 보증금 포함 여부 명시, 기존 권리와 중복 합산 금지 |

- ‘선순위비율’만 쓰지 않고 분모를 라벨·응답에 명시한다. 기존 필드의 의미를 조용히 바꾸지 말고 명시적 지표를 추가한다.
- 사용자 요구의 보증금 대비 비율도 누락하지 않도록 보정안에 포함한다. 아래 85% 고위험 정책은 시세 대비 비율과 실제 보증금 대비 비율 모두에 적용하는 보수적인 제품 규칙 제안이다. 법정 기준이나 사고 확률로 표현하지 않는다.
- 현재 `AnalysisInput`에는 실제 계약 보증금이 없으므로 입력 UI → API 검증 → 파이프라인 → 저장 DTO까지 선택 필드로 연결한다. 미입력 시 시장 평균으로 조용히 대체하지 않는다.
- 말소·부기등기 중복 합산 제외를 유지한다. 순위 판단은 접수일·접수번호 등 확인 근거를 사용하며 갑구/을구의 순위번호만 전역 비교하지 않는다. 순위 불명확 시 ‘확인된 현행 채권 기준’으로 표시한다.

#### 점수 정책 제안

서버 `calculateRiskScore`의 안전점수 방향과 A/B/C/D/F 체계를 유지한다. 85%가 단일 위험요인만으로도 D 이하가 되도록 `evaluateTotalClaims`의 감점 규모를 보정한다.

| 비율 r | 해당 채권 부담의 최소 감점 | 다른 요인이 없을 때 안전점수 상한 | 등급 |
| --- | --- | --- | --- |
| 0 ≤ r < 60% | 0 | 100 | A 가능 |
| 60 ≤ r < 70% | 15 | 85 | A 이하 |
| 70 ≤ r < 80% | 30 | 70 | B 이하 |
| 80 ≤ r < 85% | 45 | 55 | C 이하 |
| 85 ≤ r < 100% | 51 | 49 | D 이하, 고위험 |
| r ≥ 100% | 71 | 29 | F, 매우위험 |

- 제안표는 `r=C/V`와 `r=C/D`의 개별 평가에 사용한다. 동일 채권의 두 비율 감점을 단순 합산하지 않고 더 큰 감점을 채택한다. 둘 다 위험하면 근거에는 각각 표시한다.
- 기존 근저당비율 평가와 합산채권 평가의 중복 가중을 점검한다. 같은 채권 부담 계열은 최대 감점을 기본으로 묶고, 압류·경매 등 독립 위험은 추가 감점한다. 채택/제외된 요인의 설명과 합산 대상 구분을 명시한다.
- 위험요인 심각도가 높아져도 감점이 감소하지 않도록 복합위험 규칙도 점검한다. 최종 `totalDeduction`은 실제 반영된 요인 합계와 같고 `totalScore=max(0,100-totalDeduction)`을 유지한다.
- 단조성은 다른 입력·권리 상태·시간을 고정했을 때 비율이 커져도 위험점수가 내려가지 않는다는 뜻이다. 구간 내부의 동일 점수와 0/100 포화는 허용한다. 시세 하락·채권 증가 각각에 대해 검증한다.
- 금액은 원 단위 유한한 0 이상 수치, 분모는 양수만 허용한다. 음수·NaN·Infinity·범위 초과 입력은 API에서 거부한다. 분모/채권 금액 미확인은 0% 안전으로 표현하지 않는다.
- 85% 판정은 반올림 전 수치로 수행하고 화면 반올림과 판정의 관계를 안내한다. 84.99/85/85.01 및 100% 경계를 명시적으로 검증한다.
- `rights-result-styles`와 게이지에 중복된 등급 기준을 제거하고 서버와 공유하는 등급 정의를 사용한다. 위험점수는 안전점수의 역수치이며 확률이 아니다.

#### 파생 결과와 기존 이력

- `analyze-service`에서 위험 분석, 진단, V-Score 입력, 분석 근거, AI 의견에 보정된 같은 결과를 전달한다. UI에서만 숫자를 낮추는 방식은 금지한다.
- `lib/fraud-risk-model.ts`의 사기 예측 지수와 V-Score는 별도 모델이다. 이를 `100-안전점수`나 실제 사기 확률과 혼용하지 않는다. 종합 안내는 결정적 고위험 규칙을 우선하며 다른 지수가 고위험을 상쇄하지 못하게 한다.
- 각 모델의 원점수·모델명을 유지하고 ‘선순위 부담 기준 고위험’이라는 최종 판단 사유를 함께 반환한다. 85% 사례에서 최상단 결론이 ‘안전’이 되는 경로는 없어야 한다.
- 점수 규칙 버전과 적용 사유를 분석 결과 JSON에 저장한다. 과거 결과는 당시 점수로 보존하고 새 규칙으로 몰래 덮어쓰지 않는다. 버전이 다른 이력 비교에는 ‘산정 기준 변경’ 표시를 제공한다.

### 4.2 ② V-Score 설명 — P1

`RightsResult`에 V-Score 설명 패널을 추가하고 기존 V-Score DTO를 사용한다. 서버 산식을 화면에 별도 구현하지 않는다.

| 축 | 현재 기본 가중치 | 세입자용 설명 |
| --- | --- | --- |
| 등기 권리관계 | 30% | 근저당·압류 등 보증금 회수를 방해할 수 있는 권리 상태 |
| 전세가율/시세 | 25% | 시세에 비해 보증금이 얼마나 큰지와 가격 자료의 신뢰도 |
| 계약서 위험도 | 20% | 보증금 보호 관련 조항의 위험·누락 여부 |
| 임대인 위험지표 | 15% | 확보된 등기 변동 패턴 등 임대인 관련 위험 신호 |
| 지역 위험도 | 10% | 확보된 지역 위험 자료를 바탕으로 한 참고 위험 |

- 축별 `score`, `weight`, `weightedScore`, `details`, `dataAvailable`을 표시하고 ‘높을수록 안전’이라고 명시한다. 가중치와 감점 기여도(`contribution`)는 서로 다른 값임을 구분한다.
- 임대인 신용조회·지역 통계 등을 실제 조회하지 않았다면 조회한 것처럼 설명하지 않는다. 일부 데이터만 확보한 경우 근거를 한정한다.
- 미확보 축의 기본값 처리를 숨기지 않는다. 현재 산식은 미확보 축을 제외해 재정규화하는 방식이 아니며 기본값이 모두 50점인 것도 아니다. 반환된 실제 값과 근거로 ‘미확보/기본값 반영’을 표시한다.
- 전체 점수는 가중합 → 상호작용 보정 → 신뢰도에 따른 50점 방향 보정 → 반올림 순서임을 펼침 영역에서 설명한다. `confidenceLevel`은 보증금 반환 확률이 아니다.
- 분석 불가 상태에서는 V-Score도 정상 평가처럼 보여주지 않는다. 레거시 이력에 V-Score가 없으면 ‘해당 분석에서 제공되지 않음’ 표시를 사용한다.

### 4.3 ③ 분석 이력 상세 비교·PDF — P1

- `ProfileDashboardPanel`에서 모달을 별도 컴포넌트로 분리한다. 기존 목록은 경량 조회를 유지하고 모달을 열 때 본인 소유 상세를 가져온다.
- 제안 API: `GET /api/user/analyses/[id]`. 인증 후 `id + session.user.id` 조건으로 조회한다. `includePrevious=1`은 동일 회원·동일 물건·동일 분석 유형의 직전 결과를 함께 반환한다. 비교 대상도 서버에서 본인 소유를 확인한다.
- 주소는 동일 동·호수까지 식별한다. 고유 물건 식별자가 있으면 우선 사용하고 없으면 정규화 주소+동호수의 보수적인 일치만 허용한다. 도로명/지번의 동등성을 확인하지 못하면 임의 결합하지 않는다.
- 목록에 최근 5개만 보여도 비교 대상은 서버 전체 이력에서 선정한다. 선택 결과보다 이전 시각의 기록을 기본 대상으로 하고 동률 정렬 기준을 고정한다.
- 비교 항목: 분석일, 시세/실제 보증금과 출처, 안전점수·등급, 선순위 비율·전세가율, V-Score, 위험요인 추가/해소. 숫자와 단위 기준으로 차이를 계산하고 요약 문장을 파싱해 추정하지 않는다.
- 점수는 점 차이, 비율은 %p 차이로 표시한다. 안전점수 상승은 개선, 위험점수 상승은 악화로 표시한다. 입력 시세·보증금·규칙 버전 변화가 있으면 차이 원인에 함께 표시한다.
- 저장 결과 정규화 계층에서 현재 `vScore.score`를 우선하며 확인된 레거시 `finalScore` 형식만 지원한다. 미확인 값은 ‘비교 불가’로 두고 0점으로 채우지 않는다.
- 이전 결과 없음, 저장 원문 없음, 삭제된 비교 대상, 상세 조회 실패를 각각 안내한다. 재분석·AI 호출·추가 분석 횟수 차감 없이 저장된 스냅샷으로 동작한다.
- `exportToPdf`를 재사용해 주소·분석일·당시 점수·근거·버전·선택 비교 내용을 출력한다. 한국어 지원이 제한된 직접 PDF 빌더로 대체하지 않는다.
- 스크롤·접힘 영역에 잘리지 않는 전용 리포트 DOM을 만든다. 닫기·삭제 버튼과 배경 오버레이를 제외하고, 차트 렌더링 완료 후 캡처한다. 파일명에는 제어문자·경로 문자를 제거한다.
- PDF 생성 중 중복 클릭 방지, 실패 후 재시도, 모바일/다중 페이지 확인을 포함한다. 상세 데이터 확보 전에는 내보내기를 활성화하지 않는다.
- 모달은 제목 연결, 포커스 이동·복귀·가두기, Escape 닫기, 화면 내 본문 스크롤을 제공한다. `useSession` 계정 변경 시 상세/비교 캐시와 지연 응답을 무효화한다.

### 4.4 ④ 회원·주소별 계약 체크리스트 서버 저장 — P1

#### 저장 단위와 모델 제안

체크리스트 탭에 ‘계약할 집’ 선택/입력을 제공한다. 회원이 선택한 물건의 계약 준비 상태이며 소유자임을 요구하지 않는다. 로그인과 물건 식별이 완료된 뒤 복원·서버 저장한다.

신규 `JeonseChecklist` 모델을 제안한다.

| 필드 | 타입/정책 |
| --- | --- |
| `id` | String, cuid PK |
| `userId` | User FK, 삭제 시 Cascade, 세션에서만 결정 |
| `address` | String, 표시용 주소, 기존 PII 암호화 정책 적용 |
| `addressKey` | String, 서버 정규화 주소+동호수의 `hashForSearch` 결과 |
| `state` | Json, 허용된 항목 ID와 boolean 상태만 저장 |
| `schemaVersion` | Int, 체크리스트 항목 정의 버전 |
| `revision` | Int, 기본 1, 동시 수정 충돌 감지 |
| `createdAt` / `updatedAt` | 서버 시각 DateTime |

- `@@unique([userId, addressKey])`와 회원 조회용 인덱스, User 역관계를 정의한다. SQL은 동일 테이블·FK·유일제약·인덱스·기본값을 반영한다.
- 암호화 주소 자체로 유일성을 판단하지 않는다. `lib/pii-crypto-tree.ts`의 새 모델 필드·관계 매핑을 반영하고 복호화 응답도 본인에게만 제공한다.
- 주소 정규화는 공백·Unicode 표기를 정리하되 로/길·건물번호·지번·동호수를 보존한다. 식별자 변경은 새 물건으로 취급하고 기존 상태를 묵시적으로 이전하지 않는다.
- 기존 15개 항목은 서버/클라이언트 공용 정의로 분리하고 고정 ID를 유지한다. 완료 개수·총개수는 정의에서 계산하며 임의 JSON 키를 집계하지 않는다.

#### API 계약 제안

| API | 요청 | 동작 |
| --- | --- | --- |
| `GET /api/user/jeonse-checklists?address=...` | 최대 300자의 주소·동호수 | 세션 회원+서버 생성 addressKey로 조회. 미생성은 빈 상태·revision 0 반환 |
| `PUT /api/user/jeonse-checklists` | `{address, schemaVersion, expectedRevision, state}` | 생성 또는 본인 레코드 버전 조건부 갱신. 서버가 id·userId·시각을 결정 |

- `auth()`와 `NextResponse`를 사용하고 변경 요청에 기존 `validateOrigin`을 적용한다. 응답은 `Cache-Control: no-store`로 개인 데이터 캐시 혼입을 방지한다.
- JSON 파싱 실패, 허용되지 않은 필드, 빈/불완전 주소, 길이 초과, 버전 미지원, ID 0~14 밖의 키, boolean 아닌 값, 과대 본문(제안 16KB)을 서버에서 거부한다. 클라이언트 제공 userId/id/updatedAt으로 저장 범위를 바꿀 수 없다.
- 모든 조회·갱신은 세션 userId를 조건에 포함한다. 관리자/부동산 계정의 고객 대리 접근 예외는 제공하지 않는다. 후속 ID 기반 경로를 추가해도 타인·없는 ID는 동일한 404로 처리한다.
- 동일 revision 두 요청 중 하나만 원자적으로 반영한다. 생성 경합도 복합 유일키로 처리한다. 충돌은 409와 최신 본인 상태를 반환하고 자동 덮어쓰기하지 않는다.
- 미인증 401, 입력 오류 400, 본문 초과 413, 충돌 409, 내부 오류 500으로 구분한다. 로그에 주소·체크 상태·원문을 남기지 않는다.

#### 화면·전환·복구

- 비회원은 세션 내 임시 체크를 허용하되 ‘로그인 후 기기 간 저장’을 안내한다. 회원 영속 상태는 서버를 기준으로 하며 localStorage를 저장소로 재사용하지 않는다.
- 저장 중/저장 완료/저장 실패/충돌을 구분한다. 완료 시각은 서버 응답 후 표시하고 실패는 미저장 상태와 재시도를 제공한다. 연속 입력은 요청을 직렬화하거나 병합해 응답 역전으로 상태가 되돌아가지 않게 한다.
- 다른 기기·새로고침·재진입·탭 복귀 시 재조회한다. 미저장 변경과 서버 변경이 충돌하면 사용자가 확인 후 재적용한다.
- 회원/주소 전환 시 이전 요청 취소·응답 무효화와 상태 초기화를 수행해 다른 물건/회원의 체크 상태가 잠시 표시되지 않게 한다.
- 레거시 단일 키에는 회원·주소 소속 근거가 없으므로 자동 업로드하지 않는다. 로그인 후 대상 주소를 명시적으로 확인하는 일회성 가져오기를 제공한다. 허용 ID만 가져오며 기존 서버 기록은 덮어쓰지 않는다. 서버 저장 성공 뒤에만 이전 키를 제거한다.
- 후속 구현에서 `prisma/schema.prisma`와 `scripts/sql/2026-10-21-add-jeonse-checklist.sql`을 작성하되 실제 DB 적용은 실행하지 않는다. 적용 전 기능은 비활성화하고 사용 가능 상태처럼 안내하지 않는다. 실제 저장 E2E는 별도 승인된 DB 준비 이후 검증 항목으로 남긴다.

### 4.5 ⑤ 안전점수·고위험 경고 배치 — P0

- `RightsResult`의 순서를 ‘고위험 요약 → 독립된 안전점수 카드 → 지표와 점수 근거 → 상세 위험 목록’으로 구성한다. 모바일에서도 고위험 요약은 최초 영역에서 확인 가능하게 한다.
- 점수 카드에 ‘권리분석 안전점수 · 높을수록 안전’과 기준시점·산정 가능 여부를 표시한다. 고위험 요약은 별도 배경·아이콘·제목과 여백을 사용한다.
- 고위험 개수·핵심 사유·확인할 행동을 요약하고 상세 근거로 이동하게 한다. 임의의 ‘계약 가능’ 결론을 만들지 않는다. 색상 외에도 텍스트·아이콘으로 구분한다.
- ①의 동일 지표에서 점수·등급·문구가 충돌하면 서버 결과 오류로 취급한다. 서로 다른 모델 지표의 차이는 출처·범위를 설명하고 결정적 고위험 경고를 우선한다.
- `analyzable=false`, 필수 비율 계산 불가, 확인 범위 제한은 별도 상태다. ‘위험 없음’, ‘0%’, ‘안전 100점’으로 바꾸지 않는다.

### 4.6 ⑥ 전용면적 파싱 — P1

- 표제부 파싱을 건물 전체/전유부분/대지권 블록으로 분리하고 대상 동·호수의 전유부분 면적을 우선한다. 첫 번째 면적을 무조건 채택하지 않는다.
- `㎡`, `m²`, `m2`, `제곱미터`, 전각 숫자·소수점 주변 공백·행바꿈을 정규화해 같은 양수 면적으로 읽는다. 원문 근거와 표준 표시값 `84.97㎡`를 구분한다.
- 집합건물은 `exclusiveArea`를 기준으로 `area`·`propertyInfo.area`·시세 추정 입력을 일관되게 연결한다. 일반건물의 면적은 근거 없이 전용면적으로 부르지 않는다.
- 대지면적·연면적·대지권 비율·다른 호수 면적을 전용면적으로 사용하지 않는다. 후보 충돌 시 경고와 미확인 상태를 반환한다. 단위 없는 숫자에서 임의 추정하지 않는다.
- `analyze-service`의 `parseAreaValue`와 공용 면적 파서의 중복 규칙을 정리한다. 잘못된 면적이 시세 비교매물 필터까지 전달되지 않도록 연결 검증한다.

### 4.7 ⑦ 주소 완전표시 — P1

- 일반건물/집합건물의 주소 파싱을 공용 후보 추출기로 통합한다. `[도로명주소]` 표기, 숫자 포함 도로명·로/길·건물번호·부번, 지번·산번지, 특별시/광역시/특별자치시·도·시군구·읍면동리·다중 행을 지원한다.
- 표제부 물건 주소 범위에서만 후보를 선택한다. 소유자·채권자 주소, 구조·용도·면적·등기일자가 주소에 섞이지 않게 경계를 둔다.
- 도로명이 원문에 있으면 건물번호까지 완전하게 표시하고 지번도 보존한다. 지번만 있으면 지번으로 완전표시하며 없는 도로명을 만들어내지 않는다.
- 주소와 `unitNumber`를 분리 보관하고 표시할 때 중복 없이 조합한다. 원문 주소 누락·불일치 시 출처를 표시해 사용자가 대상을 확인할 수 있게 한다.
- 시장 조회용 주소와 결과 표시용 주소는 같은 물건을 가리켜야 한다. `inputSource`별 입력 주소 우선 정책을 보존하되 잘린 파싱 주소를 무조건 시장 조회에 우선하는 현재 경로를 보완한다.
- 기본정보 카드와 PDF는 긴 주소를 줄바꿈하며 말줄임만으로 숨기지 않는다. 주소 정규화는 ③ 비교와 ④ 저장에서도 재사용하되 검증되지 않은 주소 동등성을 만들지 않는다.

### 4.8 ⑧ 권리관계·종합위험도 시각화 — P1

- 기존 `RightsGraphView`와 `lib/rights-graph-engine.ts` 결과를 활용한다. 이미 있는 범례·엔진 결과 영역을 재구현하지 않고 의미·탐색·접근성을 보강한다.
- 현행 권리를 기본 표시하고 말소 권리는 별도 토글·취소선·상태 라벨로 구별한다. 부기등기는 원권리와 연결해 신규 채권처럼 중복 표현하지 않는다.
- 노드에는 권리 종류·채권 금액·접수일·확인 가능한 순위 정보를 제공한다. 클릭/키보드 선택으로 원문 근거와 ‘내 보증금 회수에 미칠 수 있는 영향’을 연다.
- 현재 노드 평균 %는 ‘권리 구성 참고 지수’처럼 범위를 명확히 바꾸고 사고 확률·종합위험도로 부르지 않는다. 엔진의 `totalSystemRisk`는 ‘권리 그래프 위험지수’로 분리한다.
- 종합위험도 표시는 ①의 공용 안전/위험점수에서만 파생하고 범례·눈금·고위험 경계·주요 감점 사유를 제공한다. 그래프 지수를 종합점수에 다시 합산하지 않는다.
- 고위험 노드가 일반 노드 수에 희석되어 종합 결론을 안전으로 바꾸지 않게 한다. 동일 위험 색상 체계를 재사용하되 각 지표의 척도 차이를 표시한다.
- 우선변제·실제 배당을 확정하려면 필요한 계약일/대항력/확정일자 등이 없을 수 있음을 상태로 표시한다. 임차인 위치를 추정 표시할 때는 가정임을 명시한다.
- 작은 화면에서 노드 겹침·긴 이름·금액을 처리하고 텍스트 목록/표로 같은 내용을 제공한다. 말소만 존재/권리 없음/엔진 결과 없음은 정상 빈 상태로 안내한다.

### 5.2 개인 데이터·접근 제어

- 신규 상세/비교/체크리스트 API는 모든 경로에서 인증과 본인 조건을 함께 확인한다. 사용자가 주소를 안다고 타인의 기록에 접근할 수 없어야 한다.
- 주소를 암호화하는 기존 정책과 검색용 HMAC을 재사용하고 모델 관계 매핑 누락을 검증한다. 암호문에 일반 문자열 검색·유일성 검사를 적용하지 않는다.
- 응답 DTO는 필요한 필드만 제공한다. 원문·소유자/채권자 개인정보는 기존 공개 범위를 넓히지 않는다. 에러에는 DB 스택·쿼리·PII를 노출하지 않는다.
- 사용자 입력을 포함한 설명·주소·요약은 일반 텍스트로 렌더링한다. PDF 리포트에서도 HTML 직접 삽입으로 검증을 우회하지 않는다.

## 8. 완료 정의와 인계

기획 완료는 기존 원인을 근거와 함께 설명하고, 8건 각각의 사용자 가치·기술 계약·우선순위·수용 기준을 이 문서에 명시한 상태다.

구현 완료는 점수 모순이 서버 산식부터 해소되고, 파싱·설명·비교·PDF·체크리스트·그래프까지 같은 정의와 본인 권한을 유지하며 검증 증거가 있는 상태다. DB 적용은 별도 작업으로 남기고 코드/SQL 산출과 운영 활성화를 구분한다.

후속 상세 설계에서는 이 문서의 제안 점수표, 두 분모에 대한 85% 보수 규칙, 실제 계약 보증금 필드명, 물건 식별 계약을 함께 확정한다. 어떤 세부안을 택하더라도 **85% 고위험·단조성·본인 권한·입력 검증·500줄 제한·DB 미적용** 조건은 완화하지 않는다.
